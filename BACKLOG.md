### Use-case анализ «Проектирование / Артефакты / Диаграммы» и решения (2026-11-07, не закоммичено)

Системная проблема была: источник правды архитектуры размазан на два хранилища
(`c4_models` JSON и `artifacts.diagram_code`), связь — только ручной экспорт.

## 📖 Обзор — человекочитаемая вьюха архитектуры (use case согласован 2026-11-07)

**Проблема:** вся архитектура и документы существуют только как markdown-исходники в
textarea — человекочитаемого представления нет; ревьюеру нечего «самому посмотреть»,
кроме исходников и AI-находок. Референсы: Structurizr documentation view (Simon Brown —
markdown + встроенные диаграммы + ADR, единый навигируемый документ), Backstage TechDocs
(reader отделён от editor, рендер внутри портала), arc42 (фиксированная структура секций).

**Use case (сценарии):**
1. *Ревьюер изучает пакет перед решением* — открывает пакет одним кликом с вкладки
   «Ревью» и читает как документ: Vision (с C4 L1) → ADR → Deployment → API →
   модель данных → NFR → Threat Model → Config/Build → DRP, с оглавлением и статусами.
2. *Автор читает пакет перед отправкой* — тот же вид глазами ревьюера; «Редактировать»
   ведёт в существующие вкладки (редактирование не дублируется).
3. *Показать кому-то* — ссылка на пакет вместо скриншотов; экспорт вне MVP.

**Решения по вопросам (выбрано):** отдельная read-only вьюха «Обзор» (не режим
в «Артефактах»); рендер — расширение собственного mdLite без новых зависимостей
(GFM-таблицы, заголовки, списки, ссылки; диаграммы — уже вендоренный mermaid);
MVP — только честное чтение, без LLM-нарратива; размещение входа — по UI/UX-ревью
кнопка «Обзор» в шапке сервиса (иконка книги, рядом со статусами, активная заливка
при открытом обзоре), из ряда вкладок убрана: «Обзор» — проекция для чтения, а не
рабочий раздел (прецедент TechDocs reader); контекстные входы сохранены — кнопка
«Открыть обзор» на вкладке «Ревью» и якорные ссылки из AI-находок. Название
«Обзор» выбрано 2026-11-07: «Пакет» отклонён пользователем, «Документация» —
слишком синонимично «Артефактам»; имя подчёркивает read-only взгляд на пакет.
Роут и код остаются `packet`/`tabPacket` (переименование только в UI-надписях).

**Функциональные**
- [x] Read-only вьюха «Обзор» (любой аутентифицированный): секции в порядке
      стандарта, markdown отрендерен (mdDoc: GFM-таблицы, заголовки, списки,
      ссылки, код-фенсы; плейсхолдер-комментарии `<!-- … -->` скрыты), диаграммы
      inline (Mermaid, лениво), карточка сервиса в шапке (2026-11-07)
- [x] Оглавление со статусами (✓ заполнен / ✗ пуст) и якорями; кнопка «Редактировать»
      → вкладка «Артефакты» (2026-11-07)
- [x] Глубокие ссылки `#/service/{sid}/packet#<kind>` из AI-находок и с вкладки «Ревью»
      («Открыть обзор»); кнопка «Обзор» в шапке сервиса (2026-11-07)

**Нефункциональные**
- [ ] Читающая вьюха — канал доверия: только факты из артефактов, без AI-генерации
- [ ] Без новых зависимостей; переиспользование renderDiag/splitDiagrams

Отложено: LLM-резюме пакета (с явной маркировкой «AI-резюме», отдельно от фактов),
